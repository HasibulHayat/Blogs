# JWT Service and JWT Auth Filter in Spring Boot

<br>
<br>

## 1. What is `JwtService`?

`JwtService` is a service/helper class that handles JWT operations.

Think of it as a **JWT toolbox**.

It does not normally watch every HTTP request. Instead, other parts of
your application call it when they need to create, read, or verify a
token.

<br>

### Its main responsibilities


#### 1. Generate a JWT

After a user logs in successfully, `JwtService` can create a token
containing information about that user.

For example, it might put these claims into the token:

``` json
{
  "sub": "user-123",
  "role": "ADMIN",
  "tenant_id": "tenant-456"
}
```

The exact claims depend on your application.

#### 2. Sign the JWT

The service uses a secret cryptographic key to sign the token.

Think of the signature like a special seal:

-   Your backend creates the seal using its secret key.
-   Later, your backend checks the seal.
-   If someone changes the token without being able to create a matching
    signature, verification fails.

For HMAC-based JWT signing, the same secret key is used to sign and
verify tokens. Keep it private and secure.

#### 3. Read the JWT

The service can parse a token and retrieve its claims.

For example:

-   User ID
-   Role
-   Session ID
-   Tenant ID
-   Token version
-   Expiration time

#### 4. Validate the JWT

The service can check whether:

-   The token has a valid signature.
-   The token has not expired.
-   The token is correctly formatted.

The exact checks depend on how the parser is configured.

A valid signature does not automatically mean the user's account or
session is still active. Those checks need additional application logic.

<br>

### Example: a simple `JwtService`

This is a teaching example to show the responsibilities. It is not a
complete production-ready implementation.

``` java
@Service
public class JwtService {

    private final SecretKey signingKey;

    public JwtService(SecretKey signingKey) {
        this.signingKey = signingKey;
    }

    // Create a token for a user
    public String generateToken(String userId, String role) {

        Instant now = Instant.now();

        return Jwts.builder()
                .subject(userId)
                .claim("role", role)
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plusSeconds(900)))
                .signWith(signingKey)
                .compact();
    }

    // Read and verify the token
    public Claims extractAllClaims(String token) {

        return Jwts.parser()
                .verifyWith(signingKey)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }

    // Get the user ID
    public String extractUserId(Claims claims) {
        return claims.getSubject();
    }

    // Get the user's role
    public String extractRole(Claims claims) {
        return claims.get("role", String.class);
    }
}
```

<br>

Understand the methods:

```
  -----------------------------------------------------------------------
  Method                              What it does
  ----------------------------------- -----------------------------------
  `generateToken()`                   Creates and signs a JWT.

  `extractAllClaims()`                Parses the JWT, verifies its
                                      signature, and returns its payload.

  `extractUserId()`                   Gets the user ID from the claims.

  `extractRole()`                     Gets the role from the claims.
  -----------------------------------------------------------------------

```

The number `900` in `plusSeconds(900)` means the example token expires
after 900 seconds, or 15 minutes.

## 2. What is `JwtAuthFilter`?

`JwtAuthFilter` is a Spring Security filter that checks incoming HTTP
requests for a JWT.

Think of it as a **security guard at the entrance of your backend**.

When a request arrives, the filter gets an opportunity to inspect it
before it reaches your controller.

Its job is not to create tokens. Its job is to use a token sent with a
request to establish the user's authentication.

<br>

### Its main responsibilities

#### 1. Inspect the request

The filter checks the incoming HTTP request.

For example:

``` http
GET /api/profile
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

The token is sent in the `Authorization` header.

#### 2. Find the Bearer token

The filter checks whether the header starts with:

``` text
Bearer
```

If it does, it extracts the token text after `Bearer`.

For example:

``` text
Bearer abc.def.ghi
```

The extracted token is:

``` text
abc.def.ghi
```

#### 3. Ask `JwtService` to verify and read it

The filter does not need to implement cryptographic signature checking
itself.

It calls methods from `JwtService`.

For example:

``` java
Claims claims = jwtService.extractAllClaims(token);
```

If the token is invalid or expired, parsing normally throws an
exception. The filter must handle that failure safely.

#### 4. Identify the user

The filter can read the user's ID and other required information from
the claims.

For example:

``` java
String userId = jwtService.extractUserId(claims);
```

Depending on your application's design, the filter may also load the
user from the database or check the session.

#### 5. Set authentication in Spring Security

This is one of the most important jobs of the filter.

After the token has been verified and the user has been identified, the
filter can create an `Authentication` object and place it in Spring
Security's `SecurityContextHolder`.

In simple language, it tells Spring Security:

> This request has been authenticated as this user.

Then Spring Security can use that authentication when applying
authorization rules.

#### 6. Continue the filter chain

If the filter has processed the request successfully, it normally allows
the request to continue through the remaining filters and eventually
toward the controller.

A filter does not automatically grant permission to every endpoint.
Spring Security still applies its authorization rules.

<br>

## 3. Example: a simplified `JwtAuthFilter`

The following example is for learning. Real applications may also load
users from a database, check session status, handle public endpoints,
and use a custom authentication entry point.

``` java
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    private final JwtService jwtService;

    public JwtAuthFilter(JwtService jwtService) {
        this.jwtService = jwtService;
    }

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain
    ) throws ServletException, IOException {

        String authHeader = request.getHeader("Authorization");

        // Is there a Bearer token?
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        // Get the token after "Bearer "
        String token = authHeader.substring(7);

        try {
            // Verify the token and read its claims
            Claims claims = jwtService.extractAllClaims(token);

            // Read user information
            String userId = jwtService.extractUserId(claims);
            String role = jwtService.extractRole(claims);

            // Create Spring Security authorities
            var authorities = List.of(
                    new SimpleGrantedAuthority("ROLE_" + role)
            );

            // Create an authenticated Spring Security object
            Authentication authentication =
                    new UsernamePasswordAuthenticationToken(
                            userId,
                            null,
                            authorities
                    );

            // Store authentication for this request
            SecurityContextHolder.getContext()
                    .setAuthentication(authentication);

        } catch (JwtException | IllegalArgumentException exception) {
            SecurityContextHolder.clearContext();
        }

        // Continue processing the request
        filterChain.doFilter(request, response);
    }
}
```

This example shows the general idea, but it deliberately keeps user
loading and application-specific checks simple.

<br>

### Understand the important lines

#### `extends OncePerRequestFilter`

``` java
public class JwtAuthFilter extends OncePerRequestFilter
```

This uses Spring Security's `OncePerRequestFilter`.

It is designed to run once per request dispatch in the normal request
flow, rather than being repeatedly applied as a regular filter might be.

#### Read the Authorization header

``` java
String authHeader = request.getHeader("Authorization");
```

This reads the request's `Authorization` header.

#### Check for Bearer

``` java
if (authHeader == null || !authHeader.startsWith("Bearer ")) {
    filterChain.doFilter(request, response);
    return;
}
```

If the header is missing or does not start with `Bearer`, this example
does not try to parse a token. It continues the filter chain.

The endpoint may still require authentication. If it does, Spring
Security's authorization handling can reject the unauthenticated request
later.

#### Extract the token

``` java
String token = authHeader.substring(7);
```

`Bearer` contains seven characters, including the space. `substring(7)`
returns the text after those characters.

#### Parse the token

``` java
Claims claims = jwtService.extractAllClaims(token);
```

The filter asks `JwtService` to parse the token and verify its
signature.

If parsing fails, an exception is thrown and control moves to the
`catch` block.

#### Get the user information

``` java
String userId = jwtService.extractUserId(claims);
String role = jwtService.extractRole(claims);
```

The filter reads the user ID and role from the verified claims.

#### Create an authority

``` java
new SimpleGrantedAuthority("ROLE_" + role)
```

Spring Security uses `GrantedAuthority` values to represent permissions
or roles.

If the role is `ADMIN`, this example creates:

``` text
ROLE_ADMIN
```

The `ROLE_` prefix is a common convention used with role-based checks
such as `hasRole("ADMIN")`.

#### Create the Authentication object

``` java
new UsernamePasswordAuthenticationToken(
        userId,
        null,
        authorities
);
```

This creates a Spring Security authentication object.

In this example:

-   `userId` is the principal (who the user is).
-   `null` is the credentials (the password is not needed here).
-   `authorities` contains the user's granted role.

The constructor with authorities creates an authenticated token.

#### Save it in the SecurityContext

``` java
SecurityContextHolder.getContext()
        .setAuthentication(authentication);
```

This is a key step.

It stores the authentication for the current security context so Spring
Security can recognize the user during the request.

### Handle a bad token

``` java
catch (JwtException | IllegalArgumentException exception) {
    SecurityContextHolder.clearContext();
}
```

If parsing or the listed validation steps fail, this example clears the
security context. It does not create authentication from the invalid
token.

The filter then continues the chain. If the endpoint requires
authentication, Spring Security will normally reject the unauthenticated
request.

### Continue the chain

``` java
filterChain.doFilter(request, response);
```

This passes the request to the next filter.

Eventually, the request may reach Spring MVC and your controller if the
security rules allow it.

## 4. How `JwtService` and `JwtAuthFilter` work together

This is the most important part of the guide.

### Part A: when the user logs in

``` text
1. User sends email and password
              |
              v
2. Backend checks the credentials
              |
              v
3. Login/authentication service calls JwtService
              |
              v
4. JwtService creates and signs a JWT
              |
              v
5. Backend sends the JWT to the frontend
```

Here, `JwtService` creates the token.

`JwtAuthFilter` is not responsible for creating it.

### Part B: when the user makes another request

``` text
1. Frontend sends an API request with the JWT
              |
              v
2. JwtAuthFilter receives the request
              |
              v
3. JwtAuthFilter extracts the token
              |
              v
4. JwtAuthFilter calls JwtService
              |
              v
5. JwtService verifies and parses the token
              |
              v
6. JwtAuthFilter reads the required claims
              |
              v
7. JwtAuthFilter sets Spring Security authentication
              |
              v
8. Spring Security applies authorization rules
              |
              v
9. Request reaches the controller if allowed
```

Remember:

-   `JwtService` knows how to work with JWTs.
-   `JwtAuthFilter` knows when to inspect an HTTP request and how to
    connect the token's identity to Spring Security.

## 7. What happens if the token is invalid?

Imagine the real token contains:

``` json
{
  "sub": "user-123",
  "role": "USER"
}
```

Someone changes the payload to:

``` json
{
  "sub": "user-123",
  "role": "ADMIN"
}
```

They do not have the signing key, so they cannot create a matching valid
signature.

The flow becomes:

``` text
Request arrives with modified token
              |
              v
JwtAuthFilter extracts the token
              |
              v
JwtAuthFilter asks JwtService to parse it
              |
              v
JwtService verifies the signature
              |
              v
Signature verification fails
              |
              v
No authentication is created from this token
              |
              v
Protected endpoint is rejected by security rules
```

The exact HTTP response depends on your Spring Security exception
handling and configuration. A protected endpoint commonly results in
`401 Unauthorized` when the request is unauthenticated.
